Como jQuery ejecuta esa cola en el orden en que se registró cada callback, y `inc/enqueue.php` ya hace que el script de PMPro se cargue primero (dependencia del handle `pmpro_checkout`), el campo `javascriptok` queda garantizado antes del clic automático — no es una esperanza de timing, es el mismo mecanismo que usa el propio plugin.

El webhook es solo un "avisá que hay que revisar", nunca la fuente de verdad — así, alguien que falsifique una notificación como mucho logra forzar una re-consulta inofensiva.

El campo "Rol" se mantiene de solo lectura (no tiene sentido que alguien se autoasigne otro rol) — para que conservara su layout horizontal se lo separó del formulario nuevo, ya que `.account-card__info .form-field` fuerza una fila pensada para ese único caso, no para un `<label>` + input apilados.
  - Nuevo harness [`test-account.php`](../../scratchpad) (scratchpad de pruebas, no forma parte del repo): 9 casos cubriendo el formulario de perfil (sin submit, nonce inválido, nombre vacío, correo inválido, correo de otra cuenta, guardar el propio correo sin cambiarlo, caso feliz) y las preferencias de notificación (activadas por defecto, guardado real). `inc/account.php` no tenía ningún harness dedicado hasta ahora.
